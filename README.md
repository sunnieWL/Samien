# Samien

Frontend prototype ภาษาไทยสำหรับทดสอบ workflow จัดการเอกสารกับอาจารย์ผู้สอนภาษาอังกฤษ ใช้ข้อมูลจาก PDF ตัวอย่าง 9 ฉบับ ไม่มี backend, login, OCR runtime, Google Calendar หรือการส่งเอกสารจริง

## เริ่มใช้งาน

ต้องมี Node.js ที่รองรับ Vite และ npm จากโฟลเดอร์นี้:

```powershell
npm.cmd install
npm.cmd run dev
```

เปิด URL ที่ Vite แสดง (ปกติ `http://localhost:5173/`) บน Windows PowerShell ใช้ `npm.cmd` หากนโยบายเครื่องบล็อก `npm.ps1`

โปรเจกต์นี้ติดตั้ง Vite 6, Tailwind CSS 4, FullCalendar 6.1 และ shadcn/ui components โดยตรวจรูปแบบการติดตั้งและ API จากเอกสารทางการที่ตรงรุ่น: [Vite 6](https://v6.vite.dev/guide/), [Tailwind กับ Vite](https://tailwindcss.com/docs/installation/using-vite), [FullCalendar React v6](https://legacy.fullcalendar.io/v6/react), [TimeGrid v6](https://legacy.fullcalendar.io/v6/timegrid-view) และ [shadcn/ui สำหรับ Vite](https://ui.shadcn.com/docs/installation/vite)

ตรวจงานก่อนส่ง:

```powershell
npm.cmd run typecheck
npm.cmd run build
```

แอปเริ่มที่ “รอลงนาม” ด้วยกล่องเอกสารว่าง กด “สแกนเอกสาร” เพื่อนำเข้า fixture ทั้ง 9 ฉบับ ปุ่ม “เริ่มเดโมจากกล่องว่าง” คืนสถานะว่าง และ “รีเซ็ตเป็นเอกสารครบ 9 ฉบับ” ใช้ข้ามขั้นสแกนเพื่อทดสอบ flow ถัดไป การสแกนซ้ำตรวจ `id` และคงสถานะที่ดำเนินการแล้ว

## พฤติกรรมเดโม

- เลือกหลายฉบับแล้วลงนามด้วยลายเซ็นที่วาดครั้งเดียว เปลี่ยนผลการพิจารณารายฉบับได้ การลงนามเป็นเพียง state ใน localStorage
- เมื่อเปิด “นัดหมาย” ระบบเลือกคำเชิญที่ยังรอตอบรับทั้งหมดไว้ก่อน ผู้ใช้ยกเลิกเลือกบางฉบับได้เองโดยไม่ถูกเลือกกลับระหว่างอยู่หน้านั้น
- ปฏิทินใช้เวลาที่ตรงกับ PDF เดโมแยกทั้ง 3 ฉบับ (ฉบับ 06 ปรับวันสอบเป็น 7 ต.ค.) แสดงชื่อ เวลา สถานที่ และสถานะในบล็อกงาน โดยมี “งานเดิมในปฏิทิน (ข้อมูลจำลอง)” แยกต่างหาก 1 รายการในวันที่ 6 ต.ค. 13:30–14:30 เพื่อทดลองกรณีชนกับงานที่มีอยู่ ไม่ใช่เอกสารเข้าใหม่หรือข้อมูลจาก PDF
- ก่อนสแกน ปฏิทินยังแสดงตารางสอนจำลอง 4 คาบ: จันทร์ 09:00–11:00, อังคาร 09:00–11:00, พุธ 13:00–15:00 และพฤหัสบดี 13:00–15:00 พร้อมชื่อวิชา กลุ่มเรียน และห้อง (ทั้งหมดเป็นข้อมูลแต่งสำหรับเดโม ไม่ใช่ข้อมูลจาก PDF) คาบสอนไม่ชนกับนัด 6–8 ต.ค. หรือคู่ conflict ของงานเดิม และไม่ถูกนับเป็นคำเชิญ
- ฉบับเดโมปรับสอบโครงร่างเป็น 7 ต.ค. เพื่อไม่ให้คำเชิญทั้ง 3 ฉบับชนกันเอง ระบบยังตรวจช่วงทับซ้อนระหว่างคำเชิญกับงานเดิมจำลอง การยอมรับรายการที่ชนกันต้องยืนยันชัดเจน หรือเลือกส่งคำขอเลื่อนงานเดิม/คำเชิญใหม่ผ่านอีเมลจำลอง โดยกรอกผู้รับและข้อความ คำขอเก็บใน localStorage เท่านั้น ไม่มีการส่งจริงและไม่เปลี่ยนเวลานัดโดยพลการ
- FYI มี read/unread และ mark as read แบบกลุ่ม โดยไม่สร้าง event ในปฏิทิน
- เอกสารที่ดำเนินการแล้วค้นหา กรองประเภท และเปิด PDF ต้นฉบับได้จาก “จัดเก็บแล้ว” นัดที่ตอบรับแล้วอยู่ในปฏิทินต่อ

ไม่มีการเขียนลายเซ็นลง PDF ไม่มีการส่งอีเมลหรือเชื่อม Google Calendar ผลทั้งหมดอยู่ใน browser เครื่องที่ใช้เดโม และล้างได้ด้วย reset ข้อมูล localStorage ใช้ schema version 4 และคีย์ใหม่เพื่อเริ่มเดโมจากกล่องว่าง โดยยังไม่ลบข้อมูลคีย์เดิม

## มาสคอตคลิปหนีบกระดาษ

คอมโพเนนต์ร่วม `SamienMascot` ใช้ภาพ PNG โปร่งใสจาก `public/mascot/welcome.png`, `scanning.png`, `success.png` และ `conflict.png` ตามสถานะกล่องว่าง การสแกน ผลสำเร็จ และเวลานัดชนกัน ภาพใช้พื้นที่ขนาดคงที่และ `object-fit: contain`; หากไฟล์ใดไม่มี ภาพนั้นจะถูกซ่อนโดยไม่แสดง broken image ข้อความและปุ่มทำงานต่อได้ตามปกติ ไม่ได้สร้างภาพทดแทนขึ้นมา

ระหว่างสแกน ภาพ `scanning.png` เด้งเบา ๆ สองครั้งด้วย CSS โดยไม่เพิ่มระยะเวลาสแกน และหยุด animation เมื่อผู้ใช้ตั้งค่า `prefers-reduced-motion: reduce`

## การตรวจสอบ

การตรวจสอบก่อนการเปลี่ยนแปลงครั้งนี้ครอบคลุมการลงนาม 2 ฉบับ, refresh, สแกนซ้ำ, เปิด PDF และเอกสารแนบ และสลับ week/month บน desktop/mobile การตรวจรอบล่าสุดอยู่ในหัวข้อถัดไป

ข้อจำกัด: state อยู่เฉพาะ localStorage ของ browser เครื่องนั้น การลงนามและการตอบรับเป็นการจำลอง ไม่เปลี่ยน PDF ต้นฉบับและไม่มีการส่งออกหรือเชื่อมระบบจริง การแสดง PDF ใน iframe ขึ้นกับตัวอ่าน PDF ของ browser
## อัปเดตการตรวจสอบล่าสุด

- มุมโปรไฟล์ด้านซ้ายล่างเปิดหน้าตั้งค่า แสดง Gmail และ Google Calendar ในสถานะ “ยังไม่เชื่อมต่อ” ทั้งคู่ โดยไม่มีการเชื่อมบัญชีจริง
- ตรวจใน Chrome จริงทั้งเดสก์ท็อปและ viewport มือถือ 390×844: เลือกคำเชิญ 3 ฉบับอัตโนมัติ, ยกเลิกเลือกผ่าน checkbox โดยไม่เปิดรายละเอียด, เปิดและบันทึกอีเมลขอเลื่อนแบบจำลอง, ตรวจสถานะหลังเปิดแท็บใหม่, ยอมรับ 2 นัดและเห็น badge/สถานะปฏิทินเปลี่ยน, เปิดโปรไฟล์ และดู agenda บนมือถือ หลังปรับวันฉบับ 06 เป็น 7 ต.ค. ตรวจซ้ำแล้วว่าเหลือคู่เวลาชนเฉพาะประชุมภาควิชากับงานเดิมจำลอง และ PDF ฉบับเดโมแสดงวันที่ 7 ต.ค. ตรงกับปฏิทิน
- รอบล่าสุดตรวจใน Chrome ว่าเริ่มจาก 0/0/0 แล้วสแกนเป็น 3/3/3, คำเชิญถูกเลือกอัตโนมัติ, คาบสอนกดดูรายละเอียดได้, ตอบรับ 3 นัดแล้ว empty state จัดกลางและปฏิทินยังแสดงนัดที่ยอมรับ หลังทดสอบคืนเดโมเป็นกล่องว่าง
- `npm.cmd run typecheck` และ `npm.cmd run build` ผ่าน (Vite เตือนขนาด bundle เกิน 500 kB แต่ไม่ทำให้ build ล้มเหลว)
